## 3. Rollback readiness (Monday 2 November)

- [ ] Vercel → Production deployment tile shows **Instant Rollback** available; the current production deployment (the rollback target) is noted above.
- [ ] Neon: room for one more branch; production is the default branch (the workflow's backup copies it).
- [ ] Neon restore window known: **Free plan 6 hours**. Data problems must be found within the first hours, which is why §5 checks data at T+15, T+30 and T+60 minutes.
- [ ] Rehearsed once: restore the **staging** branch to 30 minutes earlier in the Neon console (time it: ____ min), then re-run `npx prisma migrate deploy` + seed on staging.
- [ ] `docs/runbooks/rollback.md` open in a tab during the release.
- [ ] Kill switches understood (each needs a Vercel redeploy, ~2 min): `FLAG_ANALYTICS=off`, `FLAG_HIGHSCHOOL_SIGNUP=off`, `SECURITY_HEADERS=off`.
- [ ] Things a rollback does **not** undo, accepted: HSTS remembered by browsers for up to 1 day; the new service worker (`skipWaiting`) until the old one is fetched again; emails sent; analytics cookies set; additive database changes (harmless to the old code).

**Rollback triggers** (any one → Instant Rollback first, investigate after):
1. `/api/health` not 200 for more than 2 minutes after the deployment went live.
2. Sign-in fails for the test account or more than one real student report.
3. Answering or finishing a quiz fails (smoke or manual check, or quiz query 4 shows quizzes stuck).
4. 5xx errors on more than 1% of requests for 5 minutes (Vercel → Observability).
5. Wrong data shown to a student (someone else's data, wrong scores): roll back **and** follow the data steps and POPIA breach steps.
